Overload Fight Club.
The plan to make it the home of the game

Four independent audits of the codebase (data, design, performance, features), one ranked plan. The site already has things nobody else in the Overload ecosystem has. The job is to fix what's quietly wrong, make it fast, give it one voice, and then build the moments players will screenshot and post in Discord.

Reviewed at commit 10223be · 24,800 lines · React 19 + Vite, Express + SQLite, Docker on a Synology NAS. Every finding cites a file and line in the source.

Where it stands

Honest grades per lens. The foundation is strong on ambition and feature breadth. It's weak on the plumbing underneath: the stats math has bugs that change who "wins", the bundle is one giant file, and nothing on the site can be shared into Discord properly.

Features
B+
Live tracker, 8 years of games, fight-night recaps, a taunt DAW, and read/write access to the player's local game folder. Nobody else has that stack.
Data
C
Rich telemetry stored, but team wins are scored against a team that doesn't exist, durations are guessed, and kill logs mostly stop in 2022.
Design
C+
Strong identity, no system: 95 hex colors, two voices, a match page that never says who won, zero accessibility.
Efficiency
D
One 1.3 MB JS chunk, a 30 MB download on every Taunts visit, and a public URL that rebuilds all stats on the main thread.
Organization
C−
Seven files over 1,000 lines, React untyped (types package missing), no tests, 25 orphaned scripts, a password in git.

Fix first, this week

These are not polish. Each one is either a live risk or silently corrupts what the site tells players. All are small changes.

  1. A NAS SSH password is committed in plain text in three scripts (scripts/analyze_fight_nights.py:6, evaluate_thresholds.py:7, inspect_game_sample.py:6). Rotate it today, then scrub git history. The admin password also defaults to admin123 in both compose files and in server/auth.js:5-6, and the session secret falls back to a constant.
  2. Team wins are computed against teamScore.RED, but teams are BLUE and ORANGE. BLUE "wins" any game where it scored; ORANGE never wins (server/db.js:712, 2047, 2422). Every win rate, W/L record and rivalry record on the site is wrong for team modes. The fight-night service already does this correctly with RED ?? ORANGE.
  3. Anyone can freeze the site. A pilot stats cache miss runs the full stats rebuild synchronously inside the request (server/routes.js:830-832). It loads every game from both databases into memory at once (db.js:2000-2004), on a 2 GB NAS.
  4. Match durations are guessed. Live-era games have no start/end, so duration falls back to the time limit or 900 s (db.js:672-681, 2025-2034). Kills per minute, damage per minute and flight hours are all off. The real length is date − settings.start.
  5. Kill and damage logs are being thrown away. The hydrate job filters on fields the tracker never sends (db.js:554-564) so it does nothing, and the 60-second page-1 poll overwrites a hydrated game's details with the summary (db.js:1777-1782). Separately, backfill marks every game failed because db.insertGame calls module.exports inside an ES module (db.js:1751-1757).
  6. Two shipped features are dead. The events calendar never renders (COEP require-corp plus a CSP with no frame-src, server/index.js:70-74; the Google embed sends a same-site resource policy). The AI match analysis is pinned to gemini-2.0-flash (routes.js:723), which was retired, and the route has no auth, so the key is spendable by anyone.

The thesis: own pickup play

The league (otl.gg) owns standings, brackets and scheduled team play. The tracker (tracker.otl.gg) owns the raw server list. overloadmaps.com owns the files. Discord owns the conversation. None of them does what this site can already do, and that's where the energy should go:

  • Read/write access to the player's own game folder. Pilot files, keybinds, autoselect order, XP, taunt slots, with backups. No other site touches the install.
  • Eight years of kill-level history joined to a map catalog, with a threat ranking nobody else computes.
  • Fight nights detected automatically from the data, with a generated seven-part recap.
  • A taunt studio that installs straight into the game.
  • The only place the question "is anyone on tonight?" can be answered with history behind it.

So the north star is one sentence: the place an Overload player opens at 7 pm to see who's on, where to join, and how they did last night. Everything below serves that.

What the audits could not verify

  • No database file is in the worktree, so all data findings come from code and the committed sample JSON. The claim that damage rows are per-match totals rather than per-hit should be checked against a hydrated game.
  • Nav crowding between 768 px and about 1,150 px, and overflow of the hero and tab bars at 375 px, were inferred from the CSS and should be confirmed in a browser.
  • Whether the single-thread ffmpeg core still needs the cross-origin isolation headers. If not, dropping them also unblocks embeds.
  • The bundle was measured with a plain Vite build on Node 24; the Docker image uses Node 22. Numbers should be the same within a few KB.

Suggested first sprint

If one sprint had to prove the direction, do these in order. Every item is small, and together they change how the site feels on day one.

  1. Rotate the SSH password, scrub history, set real admin and session secrets.
  2. Fix BLUE/ORANGE scoring, real durations, the hydration filter and overwrite, and the backfill export bug.
  3. Lazy-load routes and mount the audio editor on demand. Delete the duplicate wasm.
  4. Remove the inline stats rebuild from the public route. Turn on WAL.
  5. Put live data first on the dashboard, add Fight Night to the nav, add the IP and a copy button to the live match page.
  6. Show the winner, score and real duration on the match page.
  7. Per-route titles and OG tags, then the Discord recap webhook.
